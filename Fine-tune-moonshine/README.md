# Fine-tune Moonshine-Base-BN: stage 1, standard Bangladeshi Bangla + phone audio

**Goal:** make `Sanjidh090/moonshine-base-bn` better on our hospital call recordings (Bangladeshi callers,
8 kHz phone audio). We go in stages and measure every stage:

| Stage | Training data | What it should teach | Status |
|---|---|---|---|
| **1** | **SUBAK.KO** (standard Bangladeshi Bangla, human-checked), 60% turned into phone audio | Correct standard Bangla + the **phone sound** | **this folder** |
| 2 | Regional dialect data + ~30% SUBAK.KO, starting from the stage 1 model | Regional callers (Sylhet, Chittagong, …) | later (example in `config.py`) |
| 3 | **Our own labelled calls** | Hospital words, our callers, the real phone line | after labelling ([../MOONSHINE_FINETUNE_PLAN.md](../MOONSHINE_FINETUNE_PLAN.md)) |

**Three ways to run the same code:**

| Where | How | Notes |
|---|---|---|
| **Kaggle** (recommended free GPU) | Upload [moonshine_finetune_kaggle_colab.ipynb](moonshine_finetune_kaggle_colab.ipynb) | ~30 GPU-h/week, 12 h sessions, runs in the background ("Save & Run All") |
| **Colab** free T4 | Upload the same notebook | Checkpoints on Google Drive; after a disconnect re-run all cells → resumes |
| **A PC with a GPU** | `python run_all.py --zip` | Section 3.1. Resumes automatically after a stop |

The notebook contains a copy of the `.py` files (it writes them to disk and runs them), so all three give the
same result. After changing a `.py` file, run `python make_notebook.py` to update the notebook.

## 1. Why SUBAK.KO for stage 1

| | Lipi-Ghor (what the model learned from) | **SUBAK.KO** | BanSpeech | niloycste68 dialect set |
|---|---|---|---|---|
| Size | ~856 h | 241 h (train 200 / valid 20 / test 20) | 6.5 h | 131 h |
| Source | YouTube (talk shows, audiobooks, films…) | Read speech in a studio + 12 h broadcast | Broadcast, 13 domains | Social media, 15 regions |
| Speakers | Bangladesh **and West Bengal** | 61 Bangladeshi speakers, 34 districts | Bangladeshi | Bangladeshi |
| Transcripts | **Mostly YouTube auto-captions** | **Human-checked**, standard spelling | Human-checked | **Machine-made** (Whisper), dialect spelling |
| License | unclear (CC-BY-4.0 tag, "non-commercial" text) | CC-BY-4.0 | CC-BY / BY-NC (card contradicts itself) | CC-BY-NC-4.0 |
| Our use | – (never test on it: the model has seen it) | **Train** (stage 1) + dev + test | **Test only** (too small) | Stage 2, maybe |

- **New information for the model:** clean, human-checked standard spelling, which YouTube captions don't give.
- **Standard Bangladeshi Bangla** (your first goal), no Indian Bengali.
- **Not in Lipi-Ghor** (its card lists only YouTube videos; SUBAK.KO's 12 h broadcast part is from YouTube,
  so a small overlap is possible).
- **Clean audio, so we can make it sound like a call**: 60% of the clips go through the phone simulation
  (8 kHz, 300–3400 Hz, G.711 µ-law, line noise) with a new random version every epoch; the other 40% stay clean,
  so the model does not forget clean audio.
- **Limit:** it is mostly *read* speech, callers talk freely. Expect better phone-audio and standard-word
  recognition, not perfect calls. The hospital words only come with stage 3.

**Do I need Lipi-Ghor in the training?** No. The model already learned what it can teach. The 40% clean
SUBAK.KO clips protect against forgetting. If the clean tests get clearly worse, lower the learning rate first.

## 2. The fine-tuning process in short

```
 ┌─────────────── DATA ───────────────┐   ┌──────── TRAINING (repeat for every batch) ────────┐
 │ download parquet files             │   │ 16 clips → collator: phone-sim (60%), pad, mask    │
 │ decode → mono → 16 kHz             │   │ model(audio, labels) → loss (cross-entropy)        │
 │ clean text (NFC, no tags/punct.)   │──►│ backprop → AdamW update (LR 3e-5, warm-up, decay)  │
 │ filter (1–20 s, ≤180 tokens, …)    │   │ every 250 updates: dev WER + checkpoint            │
 │ labels = tokens + [SEP] (no [CLS]) │   └───────────────────────┬────────────────────────────┘
 └────────────────────────────────────┘                           ▼
   BASELINE: score original model ──────────────►  FINAL: score best checkpoint, same test sets
                                                   → before/after table → zip → test on PC
```

- **Training data:** 20 of the 47 SUBAK.KO train files, spread over the whole set (more speakers and books),
  ~60 h after filtering (~30% of the clips are dropped). Clips with digits or English letters are dropped (our rule: numbers as words, English
  in Bangla script), as are clips over 20 s.
- **Dev set** (picks the best checkpoint): 300 SUBAK.KO validation clips, half clean, half phone.
- **Test sets** (never trained on): see 3.4.
- **Hyper-parameters:** LR 3e-5, 3 epochs, 32 clips per update (16 × 2), linear warm-up 10% then decay.

Key facts about **this** model, checked against the real model:

| Fact | Consequence |
|---|---|
| Input = raw 16 kHz waveform, padded to a multiple of 320 samples | Our 8 kHz calls are upsampled to 16 kHz, in training and in use |
| Labels = text tokens + `[SEP]` (id 3), **without** `[CLS]` | Checked: loss 1.78 vs 2.33 with `[CLS]`, so this matches how the model was trained |
| The model adds `[CLS]` (id 2) as first decoder input itself | We only pass `labels` |
| The saved `generation_config.json` has **wrong** ids (1/2/2) | Fixed in code; the fine-tuned model is saved with the correct one |
| Decoder has 194 positions | Labels ≤ 180 tokens, clips ≤ 20 s |

## 3. Step by step

### 3.0 Make your own call test set (do this first, ~1–2 h of work)

Everything else is measured on *simulated* phone audio. Only your real calls tell you whether the model got
better **for you**. Put short clips + correct transcripts in [own_test_set/](own_test_set/) (see its README):

```
own_test_set/call01_a.wav   own_test_set/call01_a.txt   ← correct text, standard Bangla
```

- ~15–20 calls (city + regional, inbound + outbound), cut into 5–20 s pieces, ~1 h total.
- Let the current model transcribe, then correct by hand: much faster than typing.
- Numbers as words, English words in Bangla script, no punctuation needed.
- **Never train on these.** Patient calls: they are git-ignored; on Kaggle upload them as a **private** dataset.

`baseline.py` and `evaluate_model.py` find them automatically and add an `own_test_set` row to the results.

### 3.1 On a PC with a GPU (your friend's machine)

1. Copy the project (at least `Fine-tune-moonshine/`, plus `sample-audio/` next to it). Then:
   ```bash
   cd ASR-models
   python -m venv .venv-train && source .venv-train/bin/activate      # Windows: .venv-train\Scripts\activate
   pip install torch --index-url https://download.pytorch.org/whl/cu126   # pick the CUDA build for your driver
   pip install -r Fine-tune-moonshine/requirements-train.txt
   python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"   # must print True
   ```
2. No Hugging Face token is needed (SUBAK.KO and BanSpeech are public).
3. Optional `Fine-tune-moonshine/config_local.py` (git-ignored, overrides `config.py`):
   ```python
   BATCH_SIZE = 32        # GPU with 24 GB+; 16 for 12-16 GB; 8 for 8 GB (then GRAD_ACCUM = 4)
   GRAD_ACCUM = 1         # keep BATCH_SIZE * GRAD_ACCUM = 32
   NUM_WORKERS = 4        # CPU processes preparing batches; up to your CPU cores
   # DATA_DIR = Path("/data/moonshine")   # if the default disk is small (~18 GB needed)
   # DELETE_RAW_AFTER_PREP = True         # delete the ~10 GB of downloads after preparation
   ```
4. Inside `Fine-tune-moonshine/`:
   ```bash
   python prepare_data.py --inspect   # downloads 1 file, prints example texts (raw -> label), sample rates; stops
   python run_all.py --quick          # whole pipeline with tiny data (~15 min): checks that everything works
   python run_all.py --zip            # the real run
   ```
   On Linux, so it keeps running after you log out: `nohup python run_all.py --zip > run_all.out 2>&1 &`
   (watch with `tail -f run_all.out`), or use `tmux`.

**Stopped?** Run the same command again: prepared data and baseline are skipped, training continues from the
last checkpoint (every 250 updates). Everything printed is also saved in `runs/<run>/logs/`.

### 3.2 On Kaggle (free, recommended)

1. kaggle.com → *Create → New Notebook → File → Import Notebook* → upload `moonshine_finetune_kaggle_colab.ipynb`.
2. Right panel *Settings*: **Accelerator: GPU T4 x2**, **Internet: On** (needs a phone-verified account).
   Prefer T4 over P100 (newer PyTorch builds may not support the P100).
3. Optional: your calls as a **private** dataset (*Upload → New Dataset*, folder `own_test_set` with the
   `.wav`/`.txt` pairs), then *Add Input* in the notebook.
4. Run all cells with `QUICK = True` (interactive is fine). Check the outputs.
5. Set `QUICK = False`, then **Save Version → Save & Run All (Commit)**. It runs in the background (up to 12 h),
   you can close the browser. Results are in the version's *Output* tab: `runs/<run>/results.md`,
   `final_model.zip`.
6. If it ran out of time: open the notebook, *Add Input → Your Work → this notebook's output*, Save & Run All
   again. Cell 2 copies the checkpoints back and training resumes.

### 3.3 On Colab (free T4)

1. Upload the notebook, *Runtime → Change runtime type → T4 GPU*.
2. Optional: your calls in Google Drive `MyDrive/moonshine_ft/own_test_set/`.
3. Run all with `QUICK = True`, then with `QUICK = False`. Checkpoints, logs and the final model go to
   `MyDrive/moonshine_ft/runs/` (~2 GB free space needed on Drive).
4. **Disconnected?** Reconnect and run all cells again: data preparation repeats (~20–40 min; or set
   `DATA_ON_DRIVE = True` if you have ~7 GB more space on Drive), training resumes from the last checkpoint.
   Keep the tab open and visible; free Colab stops idle sessions.

### Time estimates (T4, 60 h of data)

| Phase | T4 | Faster GPU (RTX 3090/4090) |
|---|---|---|
| Download (~10 GB) + prepare data (CPU) | 20–40 min | similar |
| Baseline (6 test sets × 300 clips, beam 5) | 10–20 min | 5 min |
| Training (3 epochs, ~1,900 updates) | ~1.5–3 h | 30–60 min |
| Final evaluation | 10–20 min | 5 min |

Estimates; the log prints the real numbers. Make the run shorter with `TRAIN_HOURS = 30` (notebook) or
`TRAIN_SOURCES[0].update(files=subakko_train_files(10), hours=30)` (config_local.py).

### 3.4 Reading the results (`runs/<run>/results.md`)

| Test set | What it tells you | Good result |
|---|---|---|
| **`own_test_set`** | **Your real calls.** The answer to "did it get better for us?" | Lower WER/CER |
| `test_subakko_phone` | Standard Bangla through a simulated phone line (in-domain) | Clearly lower |
| `test_subakko_clean` | The **same** clips without the phone line | Lower or equal |
| `test_bs_spont_phone` | Talk show / interview / drama, phone line: free speech, different from training | Lower |
| `test_bs_medicine_phone` | Medical words, phone line | Lower |
| `test_bs_spont_clean` | Free speech, clean | Not worse |
| `test_bs_clean` | News + audiobooks: **forgetting check** | Not worse than ~1–2 points |
| sample-audio | Your other recordings, transcripts side by side | Read them |

If only the SUBAK.KO rows improve, the model learned "read studio speech", not calls → more phone/conversation
data or stage 3. Baseline for orientation (original model, 80 BanSpeech talk-show clips, greedy):
clean 35.5% WER → phone-simulated 52.5% WER. That gap is what stage 1 tries to close.

### 3.5 Test on your PC

**Transcribe your recordings (any length):** put the unzipped model in `Fine-tune-moonshine/model/`, then
```
.venv\Scripts\python Fine-tune-moonshine\transcribe_calls.py --compare            # sample-audio/, fine-tuned vs original
.venv\Scripts\python Fine-tune-moonshine\transcribe_calls.py --audio "D:\calls"   # any folder or file
```
It resamples to 16 kHz and cuts long recordings into pieces of at most 20 s at pauses (not in the middle of a
word). Output: `outputs/transcripts_<time>/` with the full text, timed pieces and `report.md` (WER/CER where a
`.txt` reference is next to the audio). `--split-channels` transcribes stereo agent/caller channels separately.

**Old side-by-side report (fixed 20 s cuts):**

1. Copy `runs/<run>/final_model.zip` to your PC and unzip into `Fine-tune-moonshine/models/<run>/`.
2. From the project root:
   ```
   .venv\Scripts\python Fine-tune-moonshine\test_finetuned.py --model Fine-tune-moonshine\models\stage1_subakko_phone
   ```
   Writes `Fine-tune-moonshine/outputs/compare_<run>_<time>.md`: both transcripts, speed (RTF), WER/CER if a
   `.txt` reference is next to the audio. The folder loads directly with `MoonshineBN("<folder>")`.

## 4. What to do with the result

| Outcome | Next step |
|---|---|
| Own calls + phone tests better, clean tests OK | Stage 1 works. Keep this model as the new base (`BASE_MODEL = ".../final_model"`) for stage 2 / 3 |
| Phone tests better, own calls not | Open data differs too much from our calls → go to stage 3 (own calls) sooner |
| Clean tests clearly worse | Forgetting: `LEARNING_RATE` 1e-5, `NUM_EPOCHS` 2, `PHONE_SIM_PROB` 0.5 |
| Nothing changes | `LEARNING_RATE` 5e-5 and/or more hours (`subakko_train_files(40)`, ~120 h) |

**Stage 2 (dialects):** in `config_local.py` set `BASE_MODEL` to the stage 1 `final_model`, a new `RUN_NAME`,
and the commented-out `TRAIN_SOURCES` example from `config.py` (dialect data + other SUBAK.KO files). Note: the
niloycste68 labels are machine-made (Whisper) and in dialect spelling, and the license is non-commercial. Check
a few examples with `--inspect` first; human-labelled dialect data (Ben-10, RegSpeech12) would be better.

## 5. Troubleshooting

| Problem | Fix |
|---|---|
| `torch.cuda.is_available()` is `False` | CPU build of PyTorch installed: reinstall with the CUDA index URL (3.1). Kaggle/Colab: GPU not switched on |
| `CUDA out of memory` | `BATCH_SIZE = 8`, `GRAD_ACCUM = 4` |
| Loss is `nan` | `LEARNING_RATE = 1e-5`, or `PRECISION = "fp32"` |
| Disk full | `DELETE_RAW_AFTER_PREP = True`; fewer files/hours; `DATA_DIR` on another disk |
| Kaggle: downloads fail | Settings → Internet **On** (phone-verified account needed) |
| Kaggle: "no kernel image is available" | The GPU is too old for the installed PyTorch (P100): use T4 x2 |
| Colab: "GPU usage limit reached" | Wait (hours to a day) or use Kaggle |
| Training stopped | Run the same command / all cells again: it resumes |
| Dataloader errors on Windows | `NUM_WORKERS = 0` in `config_local.py` |
| Restart training from zero | `python train.py --fresh` |
| Own test set not found | Each audio needs a `.txt` with exactly the same name; check `OWN_TEST_DIR` printed in the log |

## 7. How the code was checked

The **scripts** were run on Windows (CPU, 2 dataloader workers) with tiny settings but the **real data**
(1 SUBAK.KO train file, SUBAK.KO validation/test files, the 6 BanSpeech files) and a 3-clip `own_test_set`:
data preparation, baseline (all 6 test sets + own test set), training with checkpoints and dev WER, evaluation
with the before/after table, `results.md` and the sample-audio transcripts all worked. Running `run_all.py`
again skipped data and baseline and resumed training from the last checkpoint. The baseline transcripts of
`sample-audio/` are the same as in the earlier comparison report.

Measured on that data: ~28% of SUBAK.KO clips contain digits and ~2% English letters (dropped by our rules), so
one train file gives ~3 h; clips are 11.6 s on average and all 16 kHz.

The **notebook** cells were checked for syntax, and its `config_local.py` cell was run with Kaggle and Colab
paths. **Not tested:** a real GPU (fp16/bf16 speed and memory), and the Kaggle/Colab-only parts (Drive mount,
`/kaggle/input` search, background "Save & Run All"). The `QUICK = True` run checks these in ~15 min.
